# 裁判策略与线上政策

## 1. 三层分离

```text
Rules Engine
  -> Tournament / Judge Policy
  -> Client UX
```

### Rules Engine

回答“规则上发生什么”，负责状态转移、合法性和结果。

### Tournament / Judge Policy

回答“线上赛事如何处理超时、漏触发、非法动作、修正和证据”，它不应偷偷改写普通规则。

### Client UX

回答“如何把状态和政策显示给玩家”，不负责决定规则结果。

## 2. 自动化级别

### Level A：无分支自动化

唯一合法目标、唯一合法位置、强制的资源支付和不影响策略的顺序，可以自动执行。日志必须包含：

```json
{
  "decision": "auto",
  "autoReason": "唯一合法目标",
  "promptId": null
}
```

### Level B：玩家选择

以下必须停在 Prompt：

- 可选触发或可选替代。
- 多个合法目标。
- 模式和顺序。
- 是否支付 Repeat、Flow、Accelerate 等额外/替代费用。
- 私密区域中的可选信息。
- 任何选择不同会产生不同合法结果的场景。

### Level C：裁判介入

以下进入 `judgeRequired`：

- 卡牌文本没有可执行的 DSL 语义。
- 官方规则和已导入勘误版本冲突。
- 回放状态哈希不一致。
- 玩家请求修正已经提交的非法 Command。
- 赛事规则对超时或违规有额外处理。

## 3. 触发政策

正式线上模式中，机器自动扫描适用触发，默认不会出现因为玩家没有点击卡牌而错过强制触发的问题。仍然保留两种模式：

- **Online Mode**：强制触发自动加入 Chain，可选触发进入 Prompt。
- **Judge Simulation**：允许模拟漏报、错误顺序和超时，用于训练和复盘。

触发必须记录：

- 触发事件和 `eventSeq`。
- 来源对象当时的 `GameObjectId`、地点、控制者和特征快照。
- 触发是否强制、是否可选。
- 是否自动选择以及原因。
- 最终是否 Finalize、Resolve、Ignored 或被 Counter。

### 3.1 Missed Trigger

`Missed Trigger` 是赛事/裁判政策，不是规则引擎的默认状态转移。实现应把它做成
`TournamentPolicyProfile` 的可替换策略，至少支持以下判断输入：

- 玩家是否在第一次可观察影响发生前明确表示知晓该触发。
- 触发是否强制、可选，以及是否需要玩家主动选择目标或模式。
- 遗漏是在当前回合被发现，还是已经跨过回合或关键阶段。
- 触发是否涉及隐藏信息、不可逆状态变化或需要随机恢复。

线上自动模式由引擎创建强制触发，因此通常不产生普通玩家漏触发；裁判模拟模式
则允许注入 `MissedTriggerObserved`，用于训练和复盘。同一回合发现遗漏时，
政策可以让下一位对手选择“立即处理”或“视为彻底错过”；跨回合遗漏默认不补，
除非当前赛事政策明确允许。可选触发在玩家完成 Finalize 时明确拒绝，应记录为
`declined`，而不是伪造为漏触发。

## 4. 循环、回溯与慢打

### 4.1 循环

- 完全确定、没有玩家选择且结果可证明终止的循环可以由引擎快捷执行，并记录
  循环摘要、迭代次数和 `autoReason`。
- 含有目标、支付、顺序、隐藏信息或对手响应的循环必须逐步生成 Prompt，
  不得以“无限循环”或客户端快捷键替代选择。
- 循环声明必须区分“重复执行效果”和“产生新的 Chain Item”；例如 Repeat
  可以在同一 Item 内重复执行，不得凭空增加第二个 Chain Item。

### 4.2 Rewind

回溯只由裁判工具发起，并写入显式 `JudgeCorrectionEvent`。政策层至少区分：

- **Simple Rewind**：没有隐藏信息、随机结果或不可逆外部影响，可以恢复到
  已保存的合法快照并重放后续 Command。
- **Complex Rewind**：涉及隐藏信息、随机结果、多个玩家已获得信息或不可逆
  状态变化，必须保存证据包，并使用赛事政策规定的随机恢复或裁判决定。

引擎不直接删除历史 Event；回放通过修正事件表达“从哪个快照、因何原因、
由谁授权、恢复到何状态”。

### 4.3 Slow Play

慢打不是固定秒数常量。计时器只提供事实，是否构成违规、是否警告或升级，
由 `TournamentPolicyProfile` 和裁判流程决定。客户端可以显示当前 Prompt、
已用时间、网络延迟和等待方，但不能因为本地 UI 渲染慢就自动判定玩家违规。

## 5. 超时策略

超时不是规则层的“自动 Pass”，而是政策层的决定：

| 场景 | 练习模式 | 赛事模式建议 |
| --- | --- | --- |
| 普通 Priority Prompt | 提示并暂停 | 按赛事时钟规则处理 |
| 可选触发 | 不替玩家选 | 按 Tournament Policy 判定是否视为拒绝 |
| 隐私选择 | 不暴露候选内容 | 由政策决定默认动作或裁判介入 |
| `judgeRequired` | 暂停 | 裁判席处理 |

客户端只显示倒计时和政策结果，不在前端写死赛事裁决。

## 6. 非法动作与修正

1. Command 在执行前通过 Timing/Permission Gate，非法 Command 不进入事件流。
2. 若客户端显示过时，返回最新 Projection 和可读错误原因。
3. 已进入 Chain 的 Item 按规则处理，不因为普通 UI 错误直接回滚。
4. 需要更正时由裁判工具创建显式 `JudgeCorrectionEvent`，包含原因、授权人、前后状态哈希和关联证据。
5. 不允许直接编辑历史事件；回放必须能看见修正点。

## 7. 重要政策案例

- Counter 不返还已经支付的费用。
- Counter 后不触发 `when played`。
- 被禁止的动作通常在 Resolve 时跳过，不把整张卡错误地判成无法 Finalize。
- 所有目标失效不代表触发不存在；要区分“触发成立”和“效果可执行”。
- 牌面朝下不等于 Ambush。
- Flow 的 Counter 去向按替代效果顺序处理。
- Cleanup 触发的能力要完成后再继续 FEPR。
- Repeat 不产生额外 Chain Item。

## 8. 裁判视图

裁判视图可以查看：

- 完整 `GameState` 和隐藏信息。
- 所有 Replacement/Prevention candidate。
- Prompt 的生成原因、可选项和超时。
- 每个 Event 的前后状态哈希。
- 规则版本、卡牌数据 digest、FAQ/勘误引用。
- 原始 Command、客户端时间和服务器接收时间。

裁判视图不能在普通对局中向玩家泄露隐藏信息；导出证据时应支持“完整裁判包”和“玩家可见包”两种级别。

## 9. 资料冲突处理

优先级建议：

1. 当前适用的官方 Tournament Rules。
2. 当前适用的官方 Core Rules。
3. 官方 FAQ、勘误和规则澄清。
4. 项目维护者整理的非官方裁判案例。
5. 社区讨论和经验。

第 4、5 层只能作为解释和测试线索，不能在没有标注的情况下覆盖官方规则。每个裁判决定都要保存来源和适用版本。
