## 1. 已定原则

1. **唯一规则版本**：目标 Core Rules **v1.5 / Radiance**（2026-10-16 生效）。引擎只实现当前版本；`rulesetVersion` 是数据（`"core-1.5"`），不是代码分支。不再为 v1.4 增加任何能力；v1.4 与 v1.5 有差异的地方一律按 v1.5 实现。
2. **不兼容旧回放**：不再要求新代码重放 journal schema 4–9 或 runtime profile P4–P9。需要回看的旧日志，用 git tag `legacy-replay-e2cbcdf` 的代码重放（调度者打 tag）。
3. **一个概念一个实现**：不再出现 `-v2/-v3`、`p4/p8` 这类并存文件。改语义就改原文件，靠测试保护。
4. **卡牌效果是数据**：每张卡的能力是 EffectIR 数据；引擎只实现通用原语。禁止为单张卡或单个机制写专门的“production services”。
5. **规则红线保留**：规则不明确或用到未实现原语的卡保持 `judge-required`，不得近似实现；`energy:null / power:null` 表示无印刷费，不得当成 0。
6. **语义规范**：`docs/rule-engine-architecture.md` 是引擎语义的规范来源（HOT FEPR、Turn State / Priority / Focus、费用计划、TargetPlan、事件/触发/替代）。本契约第 3 节按 v1.5 对它做增补；两者冲突时以本契约为准。

## 3. EffectIR v2

### 3.1 卡牌程序

```ts
interface CardProgram {
  canonicalCardId: string;           // 与 deck-catalog 对齐
  rulesetVersion: "core-1.5";
  status: "executable" | "judge-required" | "no-ability";
  judgeReason?: string;              // judge-required 时必填，写清缺哪个原语/哪条规则不明
  abilities: Ability[];
  deckbuilding?: DeckbuildingDecision[];   // v1.5：如 Neeko 的额外传奇选择
  sourceText: string;                // 原文，便于审查
}

type Ability =
  | { kind: "keyword"; keyword: KeywordId; value?: number }          // Assault 2、Shield、Deflect、Deploy、Disarm 1…
  | { kind: "triggered"; trigger: TriggerSpec; optional: boolean; body: Instruction[] }
  | { kind: "activated"; cost: CostSpec; timing: "action" | "reaction"; body: Instruction[]; restriction?: Restriction }
  | { kind: "static"; effect: ContinuousEffect; condition?: Condition }
  | { kind: "replacement"; replaces: EventPattern; with: Instruction[]; condition?: Condition }
  | { kind: "play"; cost?: CostSpec; body: Instruction[]; requirements?: Requirement[]; restriction?: Restriction };
```

### 3.2 指令

```ts
interface Instruction {
  id: string;                 // 卡内唯一，供链接引用
  op: OpcodeId;               // 对应 effects/instructions/<op>.ts
  args: Record<string, Expr>; // 值表达式：常量、对象属性、链接值、计数
  targets?: TargetSpec[];     // 选目标（会触发“被选为目标”）
  picks?: PickSpec[];         // v1.5 “pick”：非目标选择，不触发目标相关触发
  linkedTo?: string;          // 依赖前一条指令的结果
  condition?: Condition;      // v1.5：条件从句只作用于本条指令（作用范围见 3.4）
}
```

### 3.3 原语接口（每个文件实现一个）

```ts
interface InstructionDef<A> {
  op: OpcodeId;
  argsSchema: Schema<A>;                       // 校验 IR
  execute(ctx: ResolveContext, args: A): InstructionResult;
}

type InstructionResult =
  | { status: "executed"; events: GameEvent[]; linkedValues?: Record<string, Value> }
  | { status: "negated"; reason: "replaced" | "skipped" | "impossible"; events: GameEvent[] }
  | { status: "ignored"; reason: "mistargeted" | "linked-ignored" };
```

原语只能通过 `ResolveContext` 读写状态（提交游戏动作、产生事件），不能直接改 state、不能自己推进 priority。

### 3.4 v1.5 语义要求（解释器负责，原语不各自实现）

| v1.5 规则 | 契约要求 |
| --- | --- |
| 被忽略与被否定的指令 | 指令选错目标 → `ignored`，其后链接的指令也 `ignored`；因替代/跳过/不可能而失败 → `negated`，其后链接的指令仍尽可能执行 |
| 条件从句的作用范围 | `condition` 只作用于它所在的那条指令；需要作用于多条时用 `sequence` 包起来再加条件 |
| “pick” 与 “choose” | `targets` 是选目标；`picks` 不是目标，不触发“成为目标”相关触发 |
| 待结算项不能当目标 | 目标合法性检查排除 Pending 状态的链项 |
| 重新做选择 | “做新的选择”时全部重新选择（可选相同的），目标触发会再次触发 |
| 结算时检查行动 | 指令检查“你是否执行了某游戏动作”时，看的是动作是否发生，不看由谁执行 |
| 强制要求与限制 | `Requirement`（必须满足才能打出）与 `Restriction`（只能打到某处等）分开建模，在 Finalize 校验 |
| 复制图层 | 图层顺序 copy → trait → ability → arithmetic；复制游戏动作生成的对象直接以被复制特征为印刷特征，不施加复制效果 |
| 图层依赖 | 计算某对象需要引用另一对象时，先算被引用对象；互相引用时逐层同时计算 |
| 单位不能被附着 | 附着的非单位对象变成单位时立即脱离；试图把单位附着到对象上则什么也不发生 |
| Show Off | 展示时把被引用的特征值锁定进链接值，之后对象变化不影响 |
| Deploy / Disarm | 作为关键词文件实现：Deploy 改写打出位置并注册“对手在此固守时消灭”；Disarm 为攻击触发，同一单位多个 Disarm 合并为一个触发，数值相加 |
| Empower 多次 | 拥有多次 Empower 许可的对象忽略“仅在未 Empower 时”的限制；达上限时启动仍合法但无效果 |

### 3.5 交互骨架：时点、链与游戏动作（一等概念）

卡牌之间的一切交互只通过下面四个抽象发生。原语和卡牌不得绕过它们自己写流程（例如在某个原语里直接结算另一张卡的效果、自己推进回合或传递优先权）。

| 概念 | 是什么 | 谁产生 / 谁消费 |
| --- | --- | --- |
| **游戏动作**（GameAction） | 对状态的最小改变：抽、弃、移动、横置/重置、造成伤害、消灭、放逐、支付、获得能量/符文、附着/脱离、复制、展示、计分… | 只由原语经 `ResolveContext.perform(action)` 提交；**替代效果在动作执行前拦截**（可改写、跳过 → 对应指令 `negated`） |
| **时点**（TimingPoint） | 规则流程中可被触发的命名时刻：回合开始/各阶段开始与结束、清理、进入/离开区域、宣告攻击/防御、战斗伤害后、Showdown 开/关、链项 Pending/Finalize/Resolve、打出、成为目标、征服、固守、得分、“在本回合结束时”… | 由 `turn/ combat/ chain/ scoring/ events/` 在流程到达时发出；游戏动作执行后也作为时点发出（“当…被消灭时”）。时点清单是**封闭枚举**，在 `events/timing-points.ts` 定义，新增时点属契约变更 |
| **触发**（Trigger） | `TriggerSpec = { at: TimingPointId; filter: ObjectFilter/EventPattern; condition?; once?: "per-turn" \| "per-combat" … }` | 订阅时点；命中后生成待结算能力，**一律进链**（Pending → Finalize → Resolve），由 HOT FEPR 统一处理顺序（同时触发按回合顺序、各自选择排序，v1.5 规则 303.2.a） |
| **链**（Chain） | 唯一的结算栈：法术、单位/装备打出、触发能力、启动能力都作为链项 | `chain/` 实现 HOT FEPR；Priority / Focus、Action / Reaction 时机检查、Closed/Open 状态都在这里；其他模块只能“往链上加项”或“查询当前能否行动” |

- **持续效果**不进链，由 `layers/` 按图层计算（3.4 节）；“本回合”“本次战斗”等持续期限由时点驱动到期。
- **时机许可**（能否在此刻打出/启动）是 `chain/` 提供的唯一查询：`canAct(player, speed)`；卡牌只声明自己的速度（action / reaction）与限制。
- **每个关键词** = 若干触发 + 静态效果 + 费用/打出改写的组合（`effects/keywords/<kw>.ts`），本身不写流程。
- 验收方式：交互用例只写“局面 + 命令 + 期望事件序列”，事件序列里能看到时点 → 触发 → 进链 → 结算的完整路径。

### 3.6 原语接口 v1（冻结；取代 RIFT-20 的 contract.ts 草案）

依据 RIFT-9 原语清单（`docs/plans/survey/ability-templates.md` 第 4 节）。原语 = `effects/instructions/<op>.ts` 的一个 `InstructionDef`，**只能**通过 `ResolveContext` 读写。术语一律用 Riftbound 词汇（exhaust / kill / banish / recycle），不用 tap / destroy / exile。

```ts
type PlayerId = string;
/** 对象引用带入区序号：对象离开当前区域后旧引用失效，只能取最后已知信息 */
interface ObjectRef { readonly id: string; readonly zoneEntryId: number }

interface ObjectSnapshot {           // 计算完图层后的当前特征（只读）
  ref: ObjectRef; cardId: string | null; name: string;
  types: readonly string[]; tags: readonly string[]; keywords: readonly { id: string; value?: number }[];
  owner: PlayerId; controller: PlayerId;
  zone: ZoneId; location: LocationRef | null;   // base / battlefield
  might: number | null; energy: number | null; power: readonly Domain[] | null; // null = 无印刷值，不是 0
  exhausted: boolean; damage: number; stunned: boolean; buffs: number;
  attachedTo: ObjectRef | null; faceDown: boolean; isToken: boolean;
}

interface ResolveContext {
  // —— 身份 ——
  readonly source: ObjectSnapshot;          // 能力来源（已离场则为最后已知信息）
  readonly controller: PlayerId;            // 能力控制者
  readonly timingPoint: TimingPointId;      // 当前时点（契约 3.5）
  // —— 读 ——
  object(ref: ObjectRef): ObjectSnapshot | null;      // 引用已失效 → null
  lastKnown(ref: ObjectRef): ObjectSnapshot;          // 最后已知信息
  query(filter: ObjectFilter): ObjectSnapshot[];      // 非目标的集合查询（each / all）；不保证区域内顺序
  zoneSlice(player: PlayerId, zone: ZoneId, from: "top" | "bottom", count?: number): ObjectSnapshot[];
                                                      // 按区域内真实顺序取（牌库顶 / 底 N 张）；count 省略取全部；不足则全部（2026-10-16 RIFT-66 契约变更）
  targets(specId: string): ObjectRef[];               // Finalize 锁定、Resolve 重验后仍合法的目标
  picks(specId: string): readonly (ObjectRef | PlayerId | string)[]; // v1.5 pick
  player(id: PlayerId): PlayerSnapshot;               // 能量、符文池、XP、分数、手牌数…
  evaluate(expr: Expr): Value;                        // 动态数值（取值时机即调用时）
  test(cond: Condition): boolean;
  linked(key: string): Value | undefined;             // 前序指令写入的链接值
  history(q: HistoryQuery): number;                   // 本回合/本局某类事件次数（Flow、Legion、first/third）
  // —— 结算中的玩家决定（重放式挂起）——
  choose<T>(req: ChoiceRequest<T>): T;  // 有答案则返回；无答案则抛 AwaitChoice，引擎回滚本指令事务、提问、带答案重跑
  // —— 写 ——
  perform(action: GameAction): ActionOutcome;         // 经替代效果处理后执行
  link(key: string, value: Value): void;
  addContinuous(effect: ContinuousEffectSpec, duration: Duration): void;    // 交给 layers/
  registerDelayedTrigger(at: TriggerSpec, body: readonly Instruction[]): void;
}

type ActionOutcome =
  | { status: "done"; events: readonly GameEvent[]; result?: Value }   // result 如实际抽到的张数、实际伤害
  | { status: "replaced" | "prevented" | "impossible"; events: readonly GameEvent[] };

interface InstructionDef<A> {
  op: OpcodeId;                       // 与 RIFT-9 原语 id 一致，如 "effect.draw"
  argsSchema: Schema<A>;
  execute(ctx: ResolveContext, args: A): InstructionResult;  // 契约 3.3：executed / negated / ignored
}
```

**IR 中的对象引用是符号，不是运行时引用（2026-10-16 修正）**：卡牌程序是静态数据，无法知道运行时的入区序号。IR 里出现对象的地方（`Expr` 的 `object` 字段、`Condition` 中的对象、`ObjectFilter` 的锚点等）一律用符号选择器：

```ts
type ObjectSelector =
  | "self"                      // 本卡（能力宿主）
  | "source"                    // 能力来源（可能已离场 → 解释器取最后已知信息）
  | { target: string }          // TargetSpec id → ctx.targets(id)
  | { pick: string }            // PickSpec id → ctx.picks(id)
  | { linked: string };         // 前序指令写入的链接值（对象引用 / 引用列表）
```

运行时 `ObjectRef { id, zoneEntryId }` 只出现在 `ResolveContext` 及原语内部；**解释器负责把 `ObjectSelector` 解析为 `ObjectRef`**。`validateCardProgram` 校验的是选择器形状，不接受运行时 `ObjectRef`。

**原语规则**
1. 必须确定性：不读时间、不用 Math.random；洗牌、随机选择都通过 `perform({type:"shuffle"})` / `choose`。
2. 任何 `perform` 结果为 replaced / prevented / impossible → 本指令返回 `negated`（后续链接指令照常执行）；目标全部失效 → `ignored`（后续链接指令也 ignored）。
3. 不直接改状态、不推进优先权、不往链上加项（打出 / 复制打出用 `perform({type:"play"})`，由 chain/ 处理）。

**GameAction（封闭集合，由内核实现；原语任务不得增删）**

| 类别 | type |
| --- | --- |
| 区域 | `draw`、`discard`、`move-zone`（含 to: hand/deck-top/deck-bottom/trash/banishment/base/battlefield）、`recycle`、`banish`、`mill`、`shuffle`、`order-top`、`return-to-hand` |
| 场上 | `move-location`、`ready`、`exhaust`、`stun`、`kill`、`attach`、`detach`、`take-control` |
| 伤害 | `damage`（source、target、amount、combat: boolean）、`heal` |
| 资源 | `channel-rune`、`gain-energy`、`gain-power`、`pay`（finalized 费用计划）、`gain-xp`、`spend-xp` |
| 状态标记 | `buff`、`spend-buff`、`empower`、`disempower`、`add-counter`、`remove-counter` |
| 对象生成 | `create-token`（`to: "board" | "chain"`：直接创建在场上，或按 v1.5 440.2.c / 185.2.a 在链上生成待打出的 token；`ActionOutcome.result` 必须返回新对象引用）、`copy`（v1.5 复制游戏动作）、`play`（从某区域打出，可带费用改写；链上生成的 token 由它接手打出流程） |
| 信息 | `reveal`、`look`、`show-off`（三者的 `ActionOutcome.result` 必须返回实际被展示 / 查看的对象引用列表，按区域顺序） |
| 链 / 胜负 | `counter`、`score`、`win` |

**测试方式**：原语单测使用 `effects/testing/` 的参考测试内核（RIFT-46 实现，满足本接口的内存实现），不依赖真实引擎；P1 收敛后由真实内核实现同一接口，原语代码不变。

### 3.7 关键词接口（2026-10-16 冻结）

每个关键词一个文件 `packages/engine-core/src/effects/keywords/<keyword>.ts`，默认导出 `KeywordDef`，注册表按 `keyword` 字段索引（RIFT-16 生成器已支持）。关键词本身不写流程，只把自己**展开**成 3.1 的 `Ability`（触发 / 静态 / 启动 / 替代 / 打出改写），由解释器、时点与链执行。

```ts
interface KeywordDef {
  keyword: KeywordId;                       // 与卡牌文本方括号内名称一致，如 "Assault"、"Quick-Draw"
  valued: boolean;                          // 是否带数值（Assault 2、Shield 2、Deflect 1…）
  stacking: "sum" | "single" | "separate";  // 同一对象多个同名关键词：数值相加并合为一个（v1.5 Assault/Shield/Disarm）、只算一个、各自独立
  expand(input: { value?: number; host: CardContextRef }): readonly Ability[];  // 展开为 EffectIR 能力
  ruleRefs: readonly string[];              // v1.5 条目号
}
```

- 速度类关键词（Action、Reaction）展开为 `continuous.timing` 的静态能力；Mighty、Legion 等条件类展开为供 `condition` 使用的谓词能力。
- 展开结果必须通过 `validateCardProgram`；无法用现有原语表达的部分保持 `judge-required`，并在 `ruleRefs` 旁注明缺口。

## 4. 服务端与日志

- `game-server` 只有**一个**权威 runtime；“runtime profile”概念删除。
- 一种 journal 格式（`protocol` 中定义）：

```ts
interface JournalHeader {
  format: "riftbound-journal";
  formatVersion: 1;
  engineVersion: string;      // engine-core 包版本 + git 短 hash
  rulesetVersion: "core-1.5";
  catalogDigest: string;      // deck-catalog.json 的 digest
  seed: string;
  seats: SeatInfo[];
  createdAt: string;
}
// 正文：按序的 { seq, playerId, commandId(幂等键), command, acceptedAt }；事件与投影可由重放得到，不落盘
```

- **v1 扩充（依据 RIFT-8 `docs/plans/survey/game-server.md`「单 journal 建议字段」，冻结）**：在上面的最小字段之外，journal v1 必须保留以下语义（字段名以 RIFT-8 建议为准，可在实现时归组）：
  - header：`matchId/roomId`、`rosterDigest/trustedDeckDigest`、`creation.entropy/deterministicSeed`、`uidSeed`（或 UID 记录）、`creator`；
  - head：`stateVersion`、`eventSeq`、`roomVersion`、`parentJournalDigest/journalDigest`、`stateDigest`、`privateStateDigest`；
  - 每条命令：`actor`、`requestId/commandId`（幂等键）、`expectedStateVersion/expectedRoomVersion`、`payload`、`result/publicReceipt`、`appliedStateVersion`、`duplicate/rejection`、`entropyConsumed`、`projectionDigestByViewer`；
  - operations：`operationId/taskId/phase`、来源闭合证据、费用清点/支付计划/支付回执、`effectIRDigest/primitiveReceipts`、token 生灭与区域迁移、`pendingReason`（待续任务）；
  - integrity：`parentDigest/currentDigest`、CAS revision / nonce、受保护 head 引用。
  - 非法命令不写入正文，只在拒绝回执中体现；重复 `commandId` 返回原结果，不重复结算。
- 重放 = 用当前引擎从 header + 命令序列重算；`engineVersion` 不一致时允许重放但标记 `engineMismatch`，不做逐字节比较。
- 房间、会话、断线重连（基于 `stateVersion` + 事件游标）、幂等（`commandId`）、隐私投影、FileRoomStore：各一个模块，不按 profile 分叉。
