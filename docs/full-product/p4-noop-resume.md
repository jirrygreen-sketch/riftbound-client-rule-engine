# P4 空续接与持久化

`resumePending()` 先从当前已录制的真实原生 owner 建立独立 fork，再执行原生续接。只有返回 null、零熵消耗、私有摘要与双方及旁观者投影完全不变，才视为空调用；新的日志省略该条目。持久层先 load 并恢复最新受保护 Head，然后对已确认的空结果返回 null，不发布 fork、不调用 CAS。非空结果继续执行原有录制、CAS 和持久后发布路径。

旧 schema 1/2 可能已经含真实空 resume。重放先通过独立摘要与上下文准入，再临时保留这些历史调用，并逐条核对完整 observation 与 entropy。恢复后的档案保留原操作序列；全部重放通过后，新的空调用改为省略。归档数据和调用者不能选择此内部重放模式，原字节及保护闸门不变。

聚焦验证包含 setup/Main 重复空调用、旧版重放与篡改拒绝、CAS Head/receipt/字节不变、另一 owner 写入后的刷新、非空 pending 续接，以及既有幂等、冲突、失败和写后丢 ACK。服务器子任务和主控各自复验 15/15；完整工作区集成由主控后续统一验证。未 commit/push。
