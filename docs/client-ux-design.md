# 独立桌面客户端设计方案

## 1. 体验目标

客户端的核心感受是“牌桌在自动运行，玩家只在关键决策点介入”。玩家应能回答三件事：

1. 现在游戏处于什么规则状态？
2. 哪些能力已经触发、哪些选择已经锁定？
3. 我现在真正需要做的决定是什么？

界面参考 Rift Atlas 的牌桌信息密度和卡牌交互方式，也参考 YGO 生态常见的卡牌详情、响应队列、结算日志，但不复制任何站点的布局、代码、图像或品牌资产。

## 2. 视觉基线

- 基准画布：`1920x1080`。
- 最低桌面支持：`1280x800`。
- 视觉方向：深色战术牌桌、低装饰、高对比、边界清楚。
- 内容优先级：当前 Prompt > 牌桌状态 > 触发队列 > 事件日志 > 牌组和统计。
- 卡片圆角不超过 8px，避免把整页拆成层层嵌套的浮动卡片。
- 不使用纯渐变、装饰性光球或模糊背景作为主要视觉信息。
- 所有状态同时通过颜色、图标和文字表达，不能只靠颜色。

### 语义色

| 语义 | 颜色方向 | 辅助标识 |
| --- | --- | --- |
| 可操作 | 蓝 | 手形/闪电图标 + “可行动” |
| 等待决策 | 黄 | 问号/暂停图标 + Prompt |
| 增益 | 绿 | 上箭头 |
| 负面 | 红 | 警告/破坏图标 |
| 自动触发 | 紫 | 自动齿轮/闪光图标 |
| 锁定或不可用 | 灰 | 锁图标 + 禁用原因 |

## 3. 牌桌布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 对手信息 / 分数 / 回合状态       规则状态条 / 倒计时 / 设置 │
├───────────────┬───────────────────────────────┬─────────────┤
│ 对手手牌/牌库  │        主牌桌 Board          │ 触发队列     │
│ 资源/状态      │  Base / Battlefields / Chain │ 当前 Prompt  │
│               │  我方单位、装备、符文          │ 事件日志     │
├───────────────┴───────────────────────────────┴─────────────┤
│ 我方手牌、资源、可行动按钮、回合控制、快捷牌面查看          │
└─────────────────────────────────────────────────────────────┘
```

### 主牌桌

- Base 和各 Battlefield 是固定尺寸区域，避免卡牌增减导致布局抖动。
- Chain 使用横向时间线，不把视觉顺序误导成简单的“永远 LIFO”。
- Pending Item、Finalized Item、正在 Resolve、已结算使用不同状态徽标。
- 目标合法时高亮边框，目标被锁定后显示锁定标记；Resolve 时失效显示“已失效”。
- 面朝下卡显示统一背面和隐私状态，不直接把 `faceDown` 当成 `Ambush`。

### 侧栏

侧栏由三个可切换视图组成：

1. **触发队列**：按事件来源、控制者、当前阶段显示自动触发和等待 Prompt。
2. **事件日志**：展示公开事件、费用、选择、替代效果和 Cleanup 轮次。
3. **卡牌检查器**：展示卡牌文本、当前对象身份、来源快照、控制者、所有者、区域和适用持续效果。

## 4. 自动触发交互

### 4.1 强制触发

引擎检测到强制触发后：

1. 在触发队列中新增紫色条目。
2. 在来源卡上显示“已触发”徽标。
3. 如果选择唯一且无策略差异，自动完成选择并进入 Finalize。
4. 事件日志记录 `autoReason`，例如 `唯一合法目标`、`规则强制且无分支`。
5. 如果需要玩家决定，状态变为“等待决策”，暂停相关 FEPR 步骤。

### 4.2 可选触发和战略选择

以下情况必须生成 Prompt：

- `you may` 或可选替代效果。
- 两个或更多合法目标。
- 多个模式、多个支付方案或 Repeat 次数。
- 选择顺序会改变结果。
- 公开信息不足以判断唯一策略。
- 隐私区域中存在可选但不强制的牌。

Prompt 只展示当前需要的决定，不把完整规则文本堆在按钮上。规则解释放在可展开的检查器中。

### 4.3 Prompt 状态

| 状态 | 含义 | 客户端行为 |
| --- | --- | --- |
| `waiting` | 等待控制者选择 | 显示候选和确认 |
| `locked` | 选择已锁定 | 禁止修改，显示锁定时间 |
| `auto-resolved` | 已自动选择 | 显示原因和可回放入口 |
| `invalidated` | 目标/候选因状态变化失效 | 重新计算或按规则跳过 |
| `timed-out` | 赛事时限到期 | 交给 Judge Policy |
| `judge-required` | DSL/规则无法自动决定 | 暂停并请求裁判 |

## 5. 牌面与交互

- 点击卡牌打开检查器，双击不直接播放，避免误操作。
- 拖拽只用于表达 Move/Play 意图，最终仍需由引擎验证。
- 可行动卡牌显示蓝色轮廓；被规则禁止时保留可查看入口，但操作按钮禁用并显示原因。
- 目标选择使用“候选计数 + 过滤条件 + 确认”组合，不要求玩家逐张试错。
- 费用支付显示 Base、Additional、Increase、Discount、Final Total 五行；不可支付项明确标红。
- 自动触发可点击跳转来源卡和事件日志，但不能通过点击“再次触发”。

## 6. 规则状态条

顶部固定显示：

```text
回合玩家 · Phase · Neutral/Showdown · Open/Closed
Priority: 玩家名
Focus: 玩家名或无
Chain: Pending 2 / Finalized 1
Cleanup: idle / resolving
```

状态变化用短暂动效提示，但动画结束后信息必须仍然可读。关闭动画时使用静态徽标，不改变规则节奏。

## 7. 事件日志

事件日志分为：

- **公开事件**：所有玩家可见，例如某单位进入 Board、公开卡被 Counter、点数变化。
- **个人事件**：只给相关玩家，例如查看手牌、私密目标选择、牌库顶查看。
- **裁判事件**：只在裁判模式显示，例如规则版本、完整状态哈希、替代效果顺序。

日志每行至少包含：

```text
eventSeq · timestamp · actor · source · action · result · visibility
```

点击一行可以跳转到对应回放位置，但不允许把日志作为修改状态的入口。

## 8. 回放和观战

- 回放按事件推进，而不是录制 UI 动画。
- 支持暂停、单步、跳到 Prompt、跳到 Cleanup、跳到状态哈希变化。
- 可以切换“玩家视角”和“裁判视角”；玩家视角不显示隐藏信息。
- 事件日志和 Chain 轨迹同时滚动，帮助解释为什么某触发没有立即 Resolve。
- 回放导出包含规则版本、卡牌数据 digest、seed、事件流和客户端兼容版本。

## 9. 断线、超时和错误

- 断线时保留最后一个服务器确认的 Projection，显示只读状态。
- 重连后通过 `lastEventSeq` 请求补发事件；若服务器无法补齐则发送新快照。
- 普通练习模式可以显示暂停，不自动替玩家决定策略。
- 赛事模式的超时由 Judge Policy 决定，客户端只呈现结果。
- 规则引擎报错时显示“需要裁判/规则数据更新”，不显示技术堆栈给普通玩家。

## 10. 响应式和可访问性

- 桌面优先；窄屏时侧栏变为抽屉，主牌桌仍保持固定比例。
- 中文长文本可换行，卡牌名和 Prompt 不使用强制单行截断。
- 支持高对比模式、色弱模式、减少动画、字号放大和键盘导航。
- 所有图标按钮有 tooltip 和可访问名称。
- 目标高亮还要配合纹理/图标，避免红绿色盲无法区分。
- 键盘焦点不能被牌桌动画夺走。

## 11. 视觉资产策略

开发阶段使用中性占位卡框、色块和自制图标；不提交官方卡图、Riot 标志、角色立绘或从参考站点抓取的资源。后续若需要真实卡图，先完成授权和再分发评估，再接入 `AssetProvider`。
