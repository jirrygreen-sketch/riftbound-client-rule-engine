# 常见问题

## 客户端连不上服务端

先确认服务端已启动，并且客户端“服务地址”与服务端监听地址一致。默认都是
`ws://127.0.0.1:8787`。连接页的状态文字为“未连接”“连接中”“已连接”“重连中”“已断开”；
地址输入框接受 `ws://`、`wss://`、`http://`、`https://`，其中 `http(s)` 会被归一化为
`ws(s)` 并补上 `/ws`。

如果服务端改了 `PORT` 或 `HOST`，客户端的 WebSocket 地址和卡组管理页的“仓库服务地址”
都要改：房间走 WebSocket，卡牌目录与图片走 HTTP。

## 卡牌目录加载失败 / 建房后没有卡牌

服务端的 `/api/cards` 在目录文件缺失时返回 `503 catalog-unavailable`，错误文本包含
“Card catalog file not found”。在仓库根目录执行：

```bash
pnpm cards:sync
pnpm cards:images
pnpm cards:catalog
```

生成物位于 `packages/card-data/data/`，被 Git 忽略，不会出现在干净检出或打包产物里。
生成后重启服务端，再在卡组管理页点“重试”。

## 5173 端口被占用

`pnpm dev` 指向 desktop-client 的 Vite 脚本，固定 `127.0.0.1:5173` 且使用 `--strictPort`，
端口被占用时会直接失败而不会自动换端口。可以显式换端口启动：

```bash
pnpm --filter @riftbound/desktop-client exec vite --host 127.0.0.1 --port 5174 --strictPort
```

仓库的垂直切片说明也使用同样的 5174 示例。

## 服务端端口被占用或想换端口

用 `PORT` 环境变量覆盖默认的 `8787`，例如：

```bash
PORT=9000 pnpm start:server
```

同时把客户端的两个地址改成新端口。

## 重启服务端后房间没了

默认使用内存房间存储；只有设置 `RIFTBOUND_STORAGE_DIRECTORY` 才会启用文件房间存储并
在启动时恢复。启用后房间归档仍然只在服务端本地，公开接口不会下发归档内容。

## 网络中断后会怎样

客户端使用会话恢复令牌重连：状态栏显示“重连中”，连接页显示“正在恢复会话”。恢复令牌
存在当前标签页的 `sessionStorage` 中，刷新或短暂断线后可以继续原房间；如果换了浏览器
配置文件或清空了站点数据，就需要重新连接并加入房间。

## 对局停在“等待规则处理”

这表示当前卡牌效果或规则步骤尚未接入自动结算。客户端不会猜测结算，也不会让你手改
状态；这类效果在规则层保持 `judge-required` 或 `blocked`。请等待后续版本，或按裁判流程
处理。

## 卡组提交被拒绝

服务端负责构筑校验。卡组管理页的“校验卡组”会显示“服务端校验通过。”或逐条列出问题。
注意：

- 本地保存的卡组只是草稿，导入也不代表合法。
- 房间内已准备时先“取消准备”再修改或导入。
- 卡组变更后要重新点击“提交当前卡组”，否则准备按钮不可用并提示“卡组已变更，请重新提交”。

## 两台客户端怎么加入同一个房间

第一个客户端创建房间后，把“房间号”发给第二个客户端；第二个客户端连接同一服务端，
在“加入已有房间”里填房间号并点击“加入房间”。两台客户端要能访问同一个服务端地址。
浏览器中同时开两个客户端时，建议使用两个彼此隔离的浏览器配置文件：每个配置文件保留自己的
已保存卡组等本地存档，而会话恢复令牌按标签页存放在 `sessionStorage` 中。

## 回放里为什么看不到对手手牌

回放保存的是服务端发给当前视角的公开投影，对手手牌始终只显示背面与数量。回放是本机
个人记录，不是全局战绩，也不是严格引擎重放；单次最多 300 帧，本机最多 10 份。

## 安装时出现安全警告

发布产物未做代码签名与公证。macOS 首次启动可在“应用程序”里右键选择“打开”；Windows
SmartScreen 提示时选择“更多信息”再选择“仍要运行”。下载后建议先用同目录的 `.sha256`
校验。macOS 校验命令为 `shasum -a 256 -c <文件>.sha256`，Windows 可用
`certutil -hashfile <文件> SHA256`。

## 现在能打完一局官方规则吗

不能保证。本仓库仍在实现中：房间、投影、投影隐私与部分规则步骤可用，但完整官方效果、
完整开局流程与完整赛事规则尚未全部交付。界面上的可用操作与未支持提示是当前真实边界。

## 截图在哪里

用户指南里的界面文字来自源码；示意截图由本机视觉验证统一补图，当前文档中以“截图占位”
标注文件名，便于补图时替换。
